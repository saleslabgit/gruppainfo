# Архитектура

## Текущее состояние

Приложение использует стандартную структуру Laravel 12 без дополнительного архитектурного слоя:

- `app/Http` — HTTP-контроллеры и связанный с HTTP код;
- `app/Providers` — провайдеры Laravel;
- `app/Support` — небольшие общие технические классы форматирования;
- `routes/web.php` — текущий публичный тестовый маршрут;
- `resources/views` — Blade-layout и страницы;
- `public` — document root и все готовые CSS/JS-файлы;
- `config` — конфигурация Laravel;
- `tests` — unit- и feature-тесты.

Stage 1 не содержит моделей предметной области, аутентификации, авторизации и продуктовых workflow.

## Границы для следующих этапов

Когда соответствующая функциональность будет утверждена отдельными задачами:

- предметные enum и сервисы переходов должны находиться в выделенных пространствах имён внутри `app/Domain`;
- Eloquent-модели должны находиться в `app/Models` и отражать утверждённые `gp_*` таблицы;
- HTTP-контроллеры, request-валидация и middleware должны оставаться в `app/Http`;
- Blade-страницы и будущие компоненты должны оставаться в `resources/views`;
- интеграции с банком, почтой и внешним каталогом должны быть отделены от доменной логики в инфраструктурных классах.

Эти каталоги будущих модулей пока не созданы и функциональность в них не реализована.

Контроллеры и Blade-шаблоны не должны самостоятельно выполнять переходы статусов, денежную арифметику, преобразование часовых поясов или прямую работу с внешними системами.

## Дата и время

Приложение и база данных работают в UTC (`APP_TIMEZONE=UTC`). Для пользовательского отображения применяется `Europe/Minsk` через единый `App\Support\DateTimeFormatter`. В отдельных Blade-страницах не следует вручную менять часовой пояс. Логика сроков должна оставаться в UTC.

## Деньги

Денежные значения хранятся целыми числами в минорных единицах. `App\Support\MoneyFormatter` принимает только `int`, форматирует две минорные цифры и по умолчанию использует `BYN`. Арифметика через `float` запрещена.

## Frontend

Blade загружает скомпилированный Bootstrap 5.3.8 из `public/vendor/bootstrap`, затем проектный `public/app.css`. JavaScript загружается из локального Bootstrap bundle и `public/app.js`. CDN, Node.js, npm, Vite и frontend build step отсутствуют.

Docker используется только для разработки. Приложение остаётся обычным Laravel-проектом, пригодным для размещения вне Docker с document root, направленным на `public/`.
